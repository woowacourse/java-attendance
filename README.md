# java-attendance

## ✏️ 기능 구현 목록

### 입력

- [ ] 프로그램 실행 시 src/main/resources/attendances.csv에서 필요한 정보를 불러온다.
- [x] 옵션을 입력받는다.
    - [x] null 또는 공백 입력은 허용되지 않는다.
    - [x] 양 끝에 공백이 포함될 경우 제거(Trim)한다.
    - [ ] 1~4, Q, q만 입력할 수 있다.
- [x] 닉네임을 입력받는다.
    - [x] null 또는 공백 입력은 허용되지 않는다.
    - [x] 양 끝에 공백이 포함될 경우 제거(Trim)한다.
    - [ ] 등록된 크루 닉네임만 입력할 수 있다.
- [x] 시간을 입력받는다.
    - [x] null 또는 공백 입력은 허용되지 않는다.
    - [x] 양 끝에 공백이 포함될 경우 제거(Trim)한다.
    - [x] HH:mm 형식이어야 한다.
- [x] 날짜(일)을 입력받는다.
    - [x] null 또는 공백 입력은 허용되지 않는다.
    - [x] 양 끝에 공백이 포함될 경우 제거(Trim)한다.
    - [x] 1 이상, 해당 월의 마지막 날짜 이하의 값이어야 한다.

### 기능

- [ ] 옵션 1: 출석 확인
    - [ ] 닉네임과 등교 시간을 입력하여 출석할 수 있다.
    - [ ] 출석 후 출석 기록(월, 일, 요일, 시간, 출석 타입)을 반환한다.
    - [ ] 이미 출석한 경우, 중복 출석이 불가하며 수정 기능을 이용하도록 안내한다.
    - [ ] 주말에 출석을 시도하면 출석 불가를 안내한다.
- [ ] 옵션 2: 출석 수정
    - [ ] 출석 기록을 수정하려면 닉네임, 수정할 날짜, 변경할 등교 시간을 입력해야 한다.
    - [ ] 닉네임과 날짜 기준으로 기존 출석 기록을 조회하여 수정한다.
    - [ ] 수정 후, 변경 전 출석 기록(월, 일, 요일, 시간, 출석 타입)과 변경 후 출석 기록(시간, 출석 타입)을 가져온다.
- [ ] 옵션 3: 크루별 출석 기록 확인
    - [ ] 특정 크루의 출석 기록을 조회할 수 있다.
        - [ ] 주말 및 공휴일을 제외한 전날까지의 출석 기록을 가져온다.
        - [ ] 한 달간의 출석 기록(월, 일, 요일, 시간(없을 수 있음), 출석 타입)을 가져온다.
    - [ ] 특정 크루의 출석 통계를 조회할 수 있다.
        - [ ] 주말 및 공휴일을 제외한 전날까지의 출석, 지각, 결석, 총합을 가져온다.
        - [ ] 출석 통계를 기준으로 제적 대상 여부를 판별한다.
- [ ] 옵션 4: 제적 위험자 확인
    - [ ] 전날까지의 출석 기록을 바탕으로 제적 위험자를 파악한다.
    - [ ] 제적 위험자는 제적 대상자, 면담 대상자, 경고 대상자 순으로 출력한다.
        - [ ] 정렬 기준: 지각을 결석으로 간주하여 내림차순 정렬
        - [ ] 출석 상태가 동일할 경우, 닉네임 오름차순 정렬
    - [ ] 각 위험자에 대해 닉네임, 결석 횟수, 지각 횟수, 제적 상태(제적/면담/경고) 정보를 가져온다.

## ✅ 체크 리스트

### 기능 요구 사항

- [ ] 출석 시스템의 출석 확인은 크루가 캠퍼스에 들어온 후 시스템에 출석 데이터가 저장된 시간을 기준으로 한다.
- [ ] 시간은 24시간 형식만 사용한다. 예를 들어, "22:30"은 오후 10시 30분을 의미한다.
- [ ] 교육 시간은 월요일은 13:00-18:00, 화요일-금요일은 10:00-18:00이다.
    - [ ] 해당 요일의 시작 시각으로부터 5분 초과는 지각으로 간주한다.
    - [ ] 해당 요일의 시작 시각으로부터 30분 초과는 결석으로 간주한다.
    - [ ] 등교하지 않아 출석 기록이 없는 날은 결석으로 간주한다.
- [ ] 누적 지각 및 결석 횟수에 따라 경고 또는 면담을 시행한다. 또한 결석 횟수가 5회를 초과할 때 제적을 시행한다.
    - [ ] 지각 3회는 결석 1회로 간주한다.
        - [ ] 경고 대상자: 결석 2회 이상
        - [ ] 면담 대상자: 결석 3회 이상
        - [ ] 제적 대상자: 결석 5회 초과
- [ ] 캠퍼스 운영 시간은 매일 08:00~23:00이다.
- [ ] 주말 및 공휴일에는 출석을 받지 않는다.
- [ ] 출석 시스템에 등록된 크루와 12월 출석 기록은 제공된 파일(attendances.csv)에서 확인할 수 있다.
- [ ] 프로그램은 사용자가 종료할 때까지 종료되지 않으며, 해당 기능을 수행한 후 초기 화면으로 돌아간다.

### 프로그래밍 요구 사항

- [ ] 자바 코드 컨벤션을 지키면서 프로그래밍한다.
    - [ ] 기본적으로 Java Style Guide을 원칙으로 한다.
- [ ] indent(인덴트, 들여쓰기) depth를 2를 넘지 않도록 구현한다. 1까지만 허용한다.
    - [ ] 예를 들어 while문 안에 if문이 있으면 들여쓰기는 2이다.
    - [ ] 힌트: indent(인덴트, 들여쓰기) depth를 줄이는 좋은 방법은 함수(또는 메서드)를 분리하면 된다.
- [ ] 3항 연산자를 쓰지 않는다.
- [ ] else 예약어를 쓰지 않는다.
    - [ ] else 예약어를 쓰지 말라고 하니 switch/case로 구현하는 경우가 있는데 switch/case도 허용하지 않는다.
    - [ ] 힌트: if문에서 값을 반환하는 방식으로 구현하면 else 예약어를 사용하지 않아도 된다.
- [ ] 모든 기능을 TDD로 구현해 단위 테스트가 존재해야 한다. 단, UI(System.out, System.in) 로직은 제외
    - [ ] 핵심 로직을 구현하는 코드와 UI를 담당하는 로직을 구분한다.
    - [ ] UI 로직을 InputView, ResultView와 같은 클래스를 추가해 분리한다.
- [ ] 함수(또는 메서드)의 길이가 10라인을 넘어가지 않도록 구현한다.
    - [ ] 함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- [ ] 배열 대신 컬렉션을 사용한다.
- [ ] Java Enum을 적용한다.
- [ ] 모든 원시 값과 문자열을 포장한다.
- [ ] 줄여 쓰지 않는다(축약 금지)
- [ ] 일급 컬렉션을 쓴다.
