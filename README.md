# java-attendance

출석 미션 저장소

## 기능 목록

### 비즈니스 로직
- [x] 크루를 생성한다
  - 크루의 닉네임은 2글자 이상 ~ 4글자 이하다
  - 예외: 닉네임의 길이가 범위를 벗어난 경우
- [x] 출석 날짜를 생성한다
  - 예외: 등교일이 아닌 경우
    - 주말인 경우
    - 공휴일인 경우
- [x] 출석 시간을 생성한다
  - 예외: 캠퍼스 운영 시간을 벗어난 경우
    - 시작: 08:00
    - 종료: 23:00
- [x] 출석을 생성한다
  - 예외: 등교일이 아닌 경우
  - 예외: 캠퍼스 운영 시간이 아닌 경우
- [x] 출석 기록이 존재하는지 알려준다
- [x] 전체 크루 목록을 생성한다
- [x] 크루의 모든 출석 기록을 저장한다
- [x] 크루의 지정한 날짜 출석 기록이 존재하는지 알려준다
- [x] 크루의 지정한 날짜 출석 기록을 조회한다
- [x] 크루의 출석 기록을 저장한다
  - 예외: 출석 기록이 이미 존재하는 날짜에 추가하려는 경우
- [x] 크루의 출석 기록을 수정한다
  - 출석 날짜는 동일하고, 출석 시간만 변경된다
  - 예외: 크루가 존재하지 않는 경우
  - 예외: 수정하려는 날짜가 미래인 경우
  - 예외: 수정하려는 날짜가 존재하지 않는 경우
- [x] 크루의 지정한 날짜까지 출석 기록을 모두 조회한다
- [x] 크루의 지정한 날짜까지 출석 횟수를 계산한다
- [x] 크루의 지정한 날짜까지 지각 횟수를 계산한다
- [x] 크루의 지정한 날짜까지 결석 횟수를 계산한다
- [x] 크루의 제적 위험 상태를 조회한다
  - 이번 달 기록된 가장 마지막 날 까지를 기준으로 상태를 조회한다

### 프로그램 실행
- [ ] 출석 확인 기능을 실행한다
- [ ] 출석 수정 기능을 실행한다
- [ ] 크루별 출석 기록 확인 기능을 실행한다
- [ ] 제적 위험자 확인 기능을 실행한다
- [ ] 출석 시스템 프로그램을 종료한다

### 입출력
- [x] 출석 확인을 위한 크루 닉네임을 입력 받는다
- [x] 출석 확인을 위한 등교 시간을 입력 받는다
- [ ] 출석 수정할 크루 닉네임을 입력 받는다
- [ ] 출석 수정 날짜를 입력 받는다
- [ ] 출석 수정 시간을 입력 받는다
- [ ] 출석 확인 후 기록을 출력한다
  - 수정 기능 사용 안내 메시지를 출력한다
- [ ] 출석 수정 후 기록을 출력한다
  - 확인 기능 사용 안내 메시지를 출력한다
- [ ] 전체 출석 기록을 출력한다
  - 출석, 지각, 결석 횟수를 출력한다
  - 제적, 면담, 경고 대상자인지 출력한다
- [ ] 제적 위험자 기록을 출력한다

## 요구사항 분석

- 누적 지각 크루를 파악하는게 중요하다
- 결석 일수를 계산하는 과정이 중요하다
- 즉, 지각과 결석 카운팅이 중요하다
- 가장 큰 단위의 기능
  - 출석 확인 -> 조회, 저장
  - 출석 수정 -> 조회, (삭제 + 저장 or 수정(별도의 삭제 없이 새로운 값을 추가하면 바로 대체))
  - 크루별 출석 기록 확인 -> 전체 조회, 지각과 결석 카운팅
  - 제적 위험자 확인 -> 전체 조회, 지각과 결석 카운팅

---

- 출석 확인은 캠퍼스에 들어온 후 시스템에 출석 데이터가 저장된 시간을 기준으로 한다
- 시간은 24시간 형식만 사용
- 교육 시간
  - 월요일은 13:00 ~ 18:00
  - 화요일~금요일은 10:00 ~ 18:00
  - 캠퍼스 운영 시간은 08:00 ~ 23:00 -> 이 시간 외에는 기록이 남을 수 없다. -> 예외 상황
  - 주말 및 공휴일에는 기록이 남을 수 없다. -> 예외 상황
- 지각, 결석 규칙
  - 정상: 요일의 시작 시간으로부터 5분 이하 -> [08:00 ~ 시작 시간 + 00:05]
  - 지각: 요일의 시작 시간으로부터 5분 초과 -> [시작 시간 + 00:06 ~ 시작 시간 + 00:30]
  - 결석: 요일의 시작 시각으로부터 30분 초과 -> [시작 시간 + 00:30 ~ 23:00]
  - 등교하지 않아 출석 기록이 없는 날은 결석으로 간주한다 -> 기록이 없다 -> 객체 생성이 필요 없다?
- 경고, 면담, 제적 규칙
  - 제적: 결석 6회 이상
  - 면담: 결석 3회 이상
  - 경고: 결석 2회 이상
  - 없음: 결석 
  - 지각 3회는 결석 1회로 간주한다.
- 출석 시스템에 등록된 크루와 12월 출석 기록은 제공된 파일(attendances.csv)에서 확인할 수 있다.
- 프로그램은 사용자가 종료할 때까지 종료되지 않으며, 해당 기능을 수행한 후 초기 화면으로 돌아간다.
  - 어떤 입력을 받다 예외가 발생하면: 초기 화면 or 재입력을 받아야 할까?
- 출석 확인
  - 닉네임과 등교 시간 입력이 필요하다
  - 출석 후 출석 기록을 출력한다
  - 이미 출석한 경우. 즉, 해당 날짜(오늘)의 출석 기록이 존재하면 수정 기능을 이용하도록 안내한다
```text
닉네임을 입력해 주세요.
이든
등교 시간을 입력해 주세요.
09:59

12월 05일 화요일 09:59 (출석)
```
- 출석 수정
  - 닉네임, 수정 날짜, 수정 시간 입력이 필요하다
  - 수정된 출석 기록을 저장한다
  - 수정이 완료되면 변경 전과 후의 출석 기록을 출력한다
```text
출석을 수정하려는 크루의 닉네임을 입력해 주세요.
빙티
수정하려는 날짜(일)를 입력해 주세요.
3
언제로 변경하겠습니까?
09:58

12월 03일 화요일 10:07 (지각) -> 09:58 (출석) 수정 완료!
```
- 크루별 출석 기록 확인
  - 닉네임을 입력 받는다
  - 이번 달 전체 출석 기록을 출력한다
  - 출석, 지각, 결석 횟수를 출력한다
  - 제적, 면담, 경고 대상자인지 출력한다
    - 아무런 해당 사항이 없는 경우는 어떻게 처리할까?
```text
닉네임을 입력해 주세요.
빙티

이번 달 빙티의 출석 기록입니다.

12월 02일 월요일 13:00 (출석)
12월 03일 화요일 10:07 (지각)
12월 04일 수요일 10:02 (출석)
12월 05일 목요일 10:06 (지각)
12월 06일 금요일 10:01 (출석)
12월 09일 월요일 --:-- (결석)
12월 10일 화요일 10:03 (출석)
12월 11일 수요일 --:-- (결석)
12월 12일 목요일 --:-- (결석)
12월 13일 금요일 10:02 (출석)

출석: 5회
지각: 2회
결석: 3회

면담 대상자입니다.
```
- 제적 위험자 확인
  - **전날까지의 출석 기록을 바탕**으로 파악한다
  - 제적 -> 면담 -> 경고 순으로 출력한다
    - 지각을 결석으로 간주해 내림차순
    - 출석 상태가 같으면 닉네임 사전순 정렬
    - (결석 + 지각) 횟수로 내림차순 정렬 후 상태가 같으면 닉네임 기준 사전식 정렬
```text
제적 위험자 조회 결과
- 빙티: 결석 3회, 지각 4회 (면담)
- 이든: 결석 2회, 지각 5회 (면담)
- 빙봉: 결석 1회, 지각 6회 (면담)
- 쿠키: 결석 2회, 지각 3회 (면담)
- 짱수: 결석 0회, 지각 6회 (경고)
```
- 입출력 요구 사항
  - `src/main/resources/attendances.csv`를 통해 구현에 필요한 정보를 조회
    - 닉네임,출석 일시
- 예외 상황
  - 주말 및 공휴일에 출석 기록을 남기려는 경우
  - 등록되지 않은 닉네임을 입력한 경우
  - 캠퍼스 운영 시간 외에 출석 기록을 남기려는 경우

## 프로그래밍 요구 사항
- indent depth를 1까지 허용한다
- 3항 연산자를 쓰지 않는다
- else 예약어를 쓰지 않는다
  - switch/case도 허용하지 않는다
- 모든 기능을 TDD로 구현한다
  - 단 UI 관련 로직은 제외한다
- 함수 길이를 10라인 까지 제한한다
- 배열 대신 컬렉션을 사용한다
- Java Enum을 적용한다
- 모든 원시 값과 문자열을 포장한다
- 줄여 쓰지 않는다
- 일급 컬렉션을 쓴다
