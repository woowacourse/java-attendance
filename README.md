# 우아한테크코스 출석 관리 시스템

## 기능 요구사항

### 출석부 불러오기

- [x] csv 에서 지금까의 출석부들을 읽어온다.

### 출석부 목록

- [x] 크루 명단과 해당 크루의 출석부를 기록한다.
  단, 크루의 닉네임과 출석부는 기록되지 않을 수 없으며, 크루원간의 닉네임은 중복되어서는 안된다.
- [x] 크루 이름으로 해당 크루의 출석부를 반환한다.
- [x] 패널티 대상인 모든 크루들을 지각을 결석으로 간주하여
  내림차순으로, 같다면 닉네임으로 오름차순 정렬 하여 반환한다.

### 출석 상태

- [x] 출석 날짜의 시작 시간을 기준으로 30분 초과는 결석으로 간주한다.
- [x] 출석 날짜의 시작 시간을 기준으로 5분 초과는 지각으로 간주한다.
- [x] 그 외는 출석이다.
- [x] 출석시간들로 출석상태의 개수를 계산한다.

### 출석 패널티

- [x] 지각 3회는 결석 1회로 간주하여, 결석 5회 초과는 제적으로 간주한다.
- [x] 지각 3회는 결석 1회로 간주하여, 결석 3회 이상은 면담으로 간주한다.
- [x] 지각 3회는 결석 1회로 간주하여, 결석 2회 이상은 경고으로 간주한다.

### 출석 요일

- [x] 월요일은 13:00~18:00, 화요일~금요일은 10:00~18:00이다.
- [x] 주말 및 공휴일은 출석 요일로 사용하지 못한다.

### 출석 일시

- [x] 출석 날짜와 출석 시간을 기록한다. 단 기록하지 않을 순 없다.

### 출석 날짜

- [x] 출석 날짜는 당연하게도 날짜의 범위를 벗어날 순 없다.
- [x] 2024년 12월이 아니라면 기록하지 않는다.
- [x] 주말 및 공휴일은 기록하지 않는다.

### 출석 시간

- [x] 출석 시간은 당연하게도 시간의 범위를 벗어날 순 없다.
- [x] 캠퍼스 운영 시간은 매일 08:00~23:00이며, 해당 시간이 아닐 경우 기록하지 않는다.
  또한 출석 시간이 null일 시 기록이 없는 것이다.

### 출석부

- [x] 출석부는 크루, 출석 기록을 가진다. 단, 모두 기록되어야한다.
- [x] 출석부는 출석일시를 저장한다.
- [x] 출석부는 출석일시를 수정한다.
- [x] 출석부는 출석날짜로 출석일시를 반환한다.
- [x] 출석부는 출석 일시로 오름차순 정렬하여 반환한다.

### 크루

- [x] 크루는 닉네임을 가진다. 당연하게도 닉네임을 안가질 순 없다.

### 출석 기록

- [x] 출석 날짜와 출석 시간을 가진다. 단 기록 되지 않을 순 없다.
- [x] 출석 일시를 기록한다. 단 이미 기록된 출석 일시는 기록하지 않는다.
- [x] 출석 일시를 수정한다. 단 기록되지 않은 출석 일시는 수정하지 않는다.
- [x] 출석 날짜로 출석 일시를 반환한다. 단 출석 일시가 없다면 반환하지 않는다.
- [x] 모든 출석 일시를 반환한다.
  단 특정 날짜 하루 이전까지를 반환하고 기록되지 않았던 출석 날짜는 기록이 없는 것으로 반환한다

### 입력

#### 메뉴 선택

- [x] 메뉴를 출력한다. 단 종료를 선택하기 전까지는 종료되지 않는다.

#### 출석 확인

- [x] 크루의 닉네임을 입력 받는다.
- [x] 등교 시간을 입력 받는다.

#### 출석 수정

- [x] 크루의 닉네임을 입력 받는다.
- [x] 수정하려는 날짜를 입력 받는다.
- [x] 수정하려는 시간을 입력 받는다.

#### 출석 기록 확인

- [x] 크루의 닉네임을 입력 받는다.

### 출력

#### 출석 확인

- [x] 등교 시간, 출석 상태를 출력한다.

#### 출석 수정

- [x] 등교 날짜와 수정전 등교 시간과 출석 상태 수정후 등교 시간, 출석 상태를 출력한다.

#### 출석 기록 확인

- [x] 이번 달 출석 날짜와 출석 시간을 출력한다. 출석 상태들의 횟수를 출력한다.패널티에 해당한다면 출력한다.
  단 휴일은 제외한다. 또한 하루 이전까지의 기록만을 출석한다.

#### 제적 위험자 확인

- [x] 크루의 닉네임 출석 상태들의 횟수와 패널티를 출력한다. 단 지각을 결석으로 간주하여
  내림차순으로 출력해야하며, 같다면 닉네임으로 오름차순 정렬하여 출력해야한다.

## 프로그래밍 요구사항

- TDD 사이클을 엄격하게 지키며 처음부터 다시 구현해 본다.
- 기존 코드를 전부 삭제하고, 기존 코드를 참고하지 않는다.
- 구현 요구사항을 만족하는 최소한의 설계를 한다.
- 자바 코드 컨벤션을 지키면서 프로그래밍한다.
- indent(인덴트, 들여쓰기) depth를 2를 넘지 않도록 구현한다. 1까지만 허용한다.
- 3항 연산자를 쓰지 않는다.
- else 예약어를 쓰지 않는다.
- 모든 기능을 TDD로 구현해 단위 테스트가 존재해야 한다. 단, UI(System.out, System.in) 로직은 제외
- 함수(또는 메서드)의 길이가 10라인을 넘어가지 않도록 구현한다.
- 배열 대신 컬렉션을 사용한다.
- Java Enum을 적용한다.
- 모든 원시 값과 문자열을 포장한다.
- 줄여 쓰지 않는다(축약 금지).
- 일급 컬렉션을 쓴다.
